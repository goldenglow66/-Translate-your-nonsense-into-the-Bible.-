# 经意 · 圣经语义检索

说一句话，找出圣经里和你此刻**含义相近**的那句话。

中文和合本（CUV）全本 **31,103 节**经文已内置在本地，开箱即用；再接上任意
OpenAI 兼容的大模型接口，它还能听懂你的口气、帮你重新排序，并逐条讲清楚「为什么是这句」。

---

## 快速开始

双击 `start.bat`，或在命令行运行：

```bat
python server.py
```

然后打开浏览器访问 **http://127.0.0.1:8765**

端口被占用时会自动往后找（8766、8767…），启动日志里会打印实际地址。

需要 Python 3.9+，**不装任何第三方库**也能跑（只用标准库）。

---

## 两种模式

| 模式 | 是否需要网络 | 原理 | 速度 |
| --- | --- | --- | --- |
| **本地检索** | 否，完全离线 | 小句级倒排索引 + BM25 + 概念同义扩展 | ~2ms |
| **AI 深度理解** | 需要 API Key | 先让大模型把你的话翻译成「和合体」检索词，多路召回后语义重排 | 3–10s |

本地模式已经能做很多人以为只有 AI 才能做的事。比如你搜「焦虑」，和合本里根本
没有「焦虑」这个词（它写的是「忧虑」「挂虑」「思虑」），靠 `concepts.py` 里
62 组概念同义表，这个查询仍然能命中：

- 约伯记 30:27 我心里烦扰不安，困苦的日子临到我身。
- 路加福音 10:41 马大！马大！你为许多的事思虑烦扰，
- 约翰福音 14:27 你们心里不要忧愁，也不要胆怯。

## 接入大模型

点右上角「AI 设置」，填三项即可（Key 只存在你自己浏览器的 localStorage，
不外传，也不写进任何文件）：

- **Base URL**：`https://api.deepseek.com/v1`
- **API Key**：`sk-...`
- **模型**：`deepseek-chat`

面板里有 DeepSeek / OpenAI / 硅基流动 / 智谱 四个预设，点一下自动填好地址和模型名。
填完点「测试连接」确认通了，再把检索模式切到「AI 深度理解」。

任何 OpenAI 兼容接口都能用（`/chat/completions`），本地跑的 Ollama、vLLM、
LM Studio 也行，填它们各自的地址即可。

## 目录结构

```
Bible/
├─ server.py          零依赖 HTTP 服务（标准库）+ 全部 API 路由
├─ engine.py          检索引擎：小句切分、bigram 倒排、BM25、概念扩展、聚合打分
├─ concepts.py        62 组概念同义表（口语 → 和合本用词）+ 停用词
├─ llm.py             OpenAI 兼容接口封装：expand / rerank / explain
├─ build_verses.py    ChiUn.json → data/verses.json（繁转简、去空格）
├─ data/verses.json   编译好的经文数据（3.4 MB，31,103 节）
├─ _data/ChiUn.json   和合本原始数据（7.7 MB，繁体）
├─ public/            前端：index.html / style.css / app.js
├─ .cache/            索引缓存（首次运行自动生成，删掉会重建）
└─ start.bat          一键启动
```

## API

基础地址 `http://127.0.0.1:8765`。全部返回 JSON，UTF-8。

### `POST /api/search`

```json
{
  "q": "我最近很焦虑，睡不好",
  "mode": "fast",
  "limit": 10,
  "llm": { "baseUrl": "https://api.deepseek.com/v1", "apiKey": "sk-...", "model": "deepseek-chat" }
}
```

`mode` 取 `fast`（本地，默认）或 `deep`（走大模型，必须带 `llm`）。
`llm` 只在本次请求里用，不落盘。

响应：

```json
{
  "query": "我最近很焦虑，睡不好",
  "mode": "fast",
  "concepts": ["焦虑"],
  "keywords": ["忧虑", "挂虑", "思虑", "愁烦", "烦扰", "忧愁"],
  "results": [
    {
      "book": "约伯记", "bookId": 17, "chapter": 30, "verse": 27,
      "ref": "约伯记 30:27",
      "text": "我心里烦扰不安，困苦的日子临到我身。",
      "rel": 100.0
    }
  ],
  "took": 1.9,
  "warning": null
}
```

`rel` 是相关度（0–100，已归一化）。`deep` 模式下每条结果还多一个 `reason` 字段
（大模型给出的推荐理由），顶层多 `analysis` 和 `themes`。

### `POST /api/explain`

```json
{ "ref": "诗篇 23:1", "text": "耶和华是我的牧者，我必不致缺乏。", "query": "我很焦虑", "llm": { ... } }
```

返回三段式解读：`background`（背景）、`meaning`（含义）、`apply`（与你的处境的关系）。

### `POST /api/test`

用 `{"llm": {...}}` 探测接口是否可用，返回 `{"ok": true, "model": "...", "latencyMs": 123}`。

### 其余 GET 接口

| 路径 | 说明 |
| --- | --- |
| `/api/stats` | 语料统计：节数、书卷数、小句数、词条数 |
| `/api/books` | 66 卷书的中英文名与 `bookId` |
| `/api/verse?b=18&c=23&v=1` | 单节经文 |
| `/api/chapter?b=18&c=23` | 整章 |
| `/api/daily` | 今日经文（精选金句池按日期轮换） |
| `/api/random` | 随机一条精选金句 |

**注意 `b` 是 0 基索引**：创世记 = 0，约翰福音 = 42，使徒行传 = 43。

## 检索是怎么做的

简单的 `LIKE '%关键词%'` 在圣经上几乎没用，因为口语和经文用词差得太远。这里做了四件事：

1. **切小句**。一节经文中往往有几个意思独立的短句。把「耶稣回答说：马大！马大！
   你为许多的事思虑烦扰」切成小句分别建索引，才能精确定位到真正相关的那一句。
   命中后，该节的分数按 `总分 = 小句分 + 0.18 × 其余小句分` 聚合回节。

2. **中文 bigram 倒排**。不分词，按相邻两字建索引，查「焦虑」时匹配的是
   「焦虑」这个二元组的统计分布，而不是靠字典分词。

3. **概念同义扩展**。这是最关键的一步。`concepts.py` 里 62 组概念，每组是
   「触发词 → 和合本用词」，并按重要性排序：
   ```python
   {"k": "焦虑", "t": ["焦虑", "担心", "不安", "压力大", ...],
    "x": ["忧虑", "挂虑", "思虑", "愁烦", "烦扰", "忧愁", "心里不安", ...]}
   ```
   `x` 里的位置即权重（`1.0 - 0.05 × 序号`），越靠前越是这个词的核心译法。

4. **BM25 + 多路加权**。原句 bigram 只在未被概念命中时主导（权重 0.62）；
   一旦命中概念，重心转向概念扩展词（1.58），原句降权到 0.42。同时对
   「出现在 2.5% 以上小句里的高频词」直接丢弃——「知道」「时候」「心里」
   这类词在 9 万小句里到处都是，没有区分度。

已知局限：纯统计方法判断不了语境的正负。搜「我想原谅一个人」，本地模式可能把
申命记 29:20「耶和华必不饶恕他」也排上来。这正是 AI 重排存在的意义。

## 常见问题

**能直接部署到服务器上给别人用吗？**
可以，`server.py` 是纯 Python 标准库，任何能跑 Python 3.9 的地方都行。
公网部署建议在前面套一层 Nginx 做 HTTPS 和限流。

**不想让别人消耗我的 API Key？**
不要把 Key 写进服务器配置——本项目的设计是每个访问者填自己的 Key，
存在他自己的浏览器里，随请求临时转发。服务器不保存任何 Key。

**搜不到结果？**
本地模式依赖 `concepts.py` 的覆盖面。如果某个说法总是搜不准，在对应的概念组里
往 `t` 加上你的说法、往 `x` 加上和合本的译法，重启即可生效（`.cache` 不用清，
它只缓存索引不缓存词表）。
